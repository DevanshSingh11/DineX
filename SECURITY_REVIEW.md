# Security review

## Boundaries and controls

| Boundary | Implemented control | Evidence in this release |
|---|---|---|
| Public registration / platform / restaurant | CLI-only first platform account. Separate platform and restaurant credential stores and cookie paths. Tenant status and account activation are checked on protected requests. | Registration, suspension, logout, inactive-user and role tests |
| Passwords and sessions | Random salt, scrypt with N=32768, r=8, p=3 and a 32-byte derived value. Timing-safe verification uses a dummy hash for unknown users. Staff sessions use 36 random bytes, a server-side SHA-256 digest, 12-hour expiry, HttpOnly and SameSite=Strict cookies. HTTPS enables Secure. | Credential storage, cookie, login and replay checks. [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) |
| Browser writes | API mutations require a custom request header. Present Origin headers must equal the configured public origin. The API grants no cross-origin read/write permission. Browser-generated cross-origin form posts fail the header check. | Origin and write-header rejection tests. [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) |
| Restaurant ownership | Server resolves the actor from its session and derives the tenant. Tenant-scoped queries, tenant-aware foreign keys and unique constraints cover parent-child writes. Platform summaries omit individual guest lines and payment references. | Cross-tenant menu, order, checkout, table, image and role regression tests |
| Privileges and account continuity | Explicit permission sets and grants. Admins cannot manage Owners or peer Admins. Role/account updates revoke affected staff sessions. Last-active-owner and last-platform-admin rules run inside serialized transactions. | Role, grant, last-account and activation tests |
| QR and guest privacy | HMAC-SHA256 over tenant/table/rotation nonce. Fragment-based QR transport keeps the QR secret out of the initial HTTP request and access log. The client exchanges the credential, removes the fragment and uses a separate visit token in session storage. Guest endpoints return data only for that visit. | Rotation, revoked credentials, private guest history and concurrent-visit tests |
| Retained financial records | Server calculates prices in minor units, validates all options, snapshots line details, serializes reservation and bill changes, and records confirming staff. There is one payment per bill. | Replay, concurrency, adjustments, forbidden transitions, historical prices and table occupancy tests |
| Menu and branding input | Pydantic schemas reject unknown fields. Browser templates create DOM nodes and insert text without HTML interpolation. Images accept JPEG/PNG/WebP input, 3 MiB request and 12 MP pixel limits, re-encode to WebP and discard metadata. HTTPS image URLs also work. | Media validation, public-reference restriction and size checks |
| Public API load | Per-IP bounded in-memory windows cover authentication, registration, QR entry, order placement, service and guide requests. JSON bodies are limited to 192 KiB. Broad writes return a controlled retry response on database contention. | Recorded login-rate and upload-limit tests |
| Menu guide | Only available dishes from the current tenant enter ranking. Gemini interprets search requests and transcribes explicitly uploaded voice notes. The compatible provider can return dish IDs. Server-owned fields supply visible prices and ingredients. Allergy filters use explicit confirmation and recorded recipes. Incomplete records and conflicting traces are excluded, and unresolved requests go to staff. Text from the provider cannot change an order, submit a payment or become a menu fact. | Local grounding, unavailable items, unknown provider IDs, provider failure and dietary prompts |
| Website responses | Content Security Policy restricts scripts, styles and connections to the application. Referrer-Policy is no-referrer. Dynamic responses use Cache-Control no-store. Sensitive values are excluded from normal app logs and API responses. | Header checks and review of request/response field lists |

## Operational limits and decisions

- A printed QR is a possession credential. A copy can open new visits until revoked. Staff can rotate it after disclosure. Rotation blocks new writes on old visits while keeping existing orders trackable and billable. A suspended tenant's active sessions are invalidated.
- Secure the database, backups and configuration with OS permissions and encrypted storage appropriate to the host. A server administrator with write access can change database records. The application audit log is an operational history. External tamper-evident archival requires separate infrastructure.
- Use HTTPS for real diners and credentials. The local HTTP setup serves development and trusted-network testing. A TLS proxy, restore rehearsal, monitoring, retention policy, dependency review and peak-load test are deployment tasks.
- The built-in limiter is process-local. Proxy deployment should apply its own limits using a trusted client-IP configuration. Run a single application worker with this SQLite baseline. A large deployment needs controlled performance testing and a reviewed migration plan.
- Gemini receives the guest question and category names for interpretation, or the audio explicitly selected for transcription. The compatible ranking provider receives the guest question and permitted menu descriptions. Select a provider and data-handling terms suitable for the restaurant. All keys belong in the environment. A text question can contain personal information volunteered by a guest.
- Cash, UPI and card receipts require staff to verify the actual payment outside DineX. A live gateway requires merchant enrollment, a provider SDK/API, server-managed credentials, authenticated callbacks, amount/currency verification, idempotent merchant references and reconciliation before it can update a bill. Platform subscription charging and gateway refunds remain future integrations.
- This review covers implemented controls and tests. Independent security assessment, live-provider certification and production load validation remain open.
